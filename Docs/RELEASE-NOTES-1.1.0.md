# ZashDock 1.1.0

**ZashDock 1.1.0（Build 4）**，适用于 Apple Silicon、macOS 26.0+。本次将面板地址改为应用自动管理，并改进后台更新、故障恢复和原生设置。安装包与更新资产见 [GitHub Releases](https://github.com/MiracleHYH/ZashDock/releases)。

## 自动管理面板地址

- 移除原生设置中的端口输入、当前端口和手动选端口按钮。应用从 **49152–65535** 随机尝试高位端口，实际绑定并验证成功后保存，以后启动复用该地址。
- 旧配置首次升级时执行一次地址迁移。完整 LocalStorage、Remote、选中后端、网页设置、本地背景图和连接历史在新网页初始化前恢复并核验；提交前失败保留原配置和源数据。
- 已保存端口被其他程序占用时，应用自动选择其他可用地址并安全迁移，不请求占用原端口的程序。候选地址若已有业务数据会被跳过，避免覆盖其他 Origin 的内容。
- 已知 `zashboard-geoip` v2 和 `zashboard-earth-geoip` v1 可再生缓存留在源 Origin，不复制或删除其二进制数据；新地址由 Zashboard 按需重建。其他未知数据库、未知版本或不受支持的业务结构仍会中止迁移并保留数据。
- 普通配置损坏时保全原文件，并使用可确认的恢复元数据定位原网页数据；无法确认原 Origin 时停止恢复，不猜测地址，也不要求用户填写端口。

**使用精确 CORS 白名单的远程 Mihomo 服务需要注意：** 首次迁移或端口冲突后，面板 Origin 会改变。请从 **帮助 → 复制面板地址** 获取实际地址，并在远程服务中允许该地址。应用不会替用户修改远端、Surge 或系统代理配置，也不绕过浏览器 CORS 检查。成功选定的地址会被复用，不会在每次启动时重新随机。

## 原生交互改进

- 后台检查更新和下载面板资源时，当前面板保持可操作；正式切换版本或迁移数据时才短暂暂停相关操作。
- 系统菜单“检查 Zashboard 面板更新…”直接打开更新页，将检查结果、当前版本、最新版本及安装动作放在相邻位置。同一任务集中显示进度，仅在可取消阶段提供取消入口。
- 故障页突出与当前问题对应的首选恢复操作，将其他选项和技术详情折叠。错误反馈使用具体任务名称，提供就地重试，并说明原数据的保留状态。
- 更新与关于页继续明确区分 ZashDock 应用和 Zashboard 面板版本；关于页增加应用身份与用途说明，项目链接和许可分组展示。
- 文件导出超限、内容失效或格式无效时给出明确提示，保存失败时提示重试位置。取消不作为错误；可信主框架、真实点击、单次授权和 16 MiB 上限继续生效。

## 安装与应用更新

本版本继续采用 **ad hoc** 签名模式，保留 App Sandbox 与 Hardened Runtime，没有 Developer ID 签名、Apple 公证或装订。仅此模式临时包含加载 Sparkle 所需的库验证例外；共享 entitlements 和稳定 Bundle ID `app.zashdock.mac` 保持不变。

发行流程要求使用既有专用 Ed25519 密钥签名应用 ZIP 和 Sparkle Feed，并独立验证。Build 4 用于让 Build 3 及更早的安装识别更新；这些完整性检查不等同于 Apple 公证。首次从 GitHub 下载后，macOS 可能阻止启动。确认下载来源后，可按 [Apple 官方说明](https://support.apple.com/zh-cn/102445)，在“系统设置 → 隐私与安全性”选择 ZashDock 的“仍要打开”。

ZashDock 应用更新与 Zashboard 面板更新仍相互独立。面板资源继续来自上游官方 Releases，同 Origin 更新原地保留网页数据，不增加 Remote 编辑器或本地 Mihomo 内核。

## 验证与边界

本次源码的实际本地验证包括：

- Core 汇总 **83 项 / 6 suites** 通过，1 项可选官方在线下载测试按条件跳过。
- 实际 Xcode 沙箱 App **69 项通过、3 项按条件跳过、0 失败**，汇总 72 项 / 16 suites。跳过项为两项真实官方 ZIP 测试和个人后端网络测试。
- 正式 AppModel **7 个独立 PID** 跨进程回归通过，覆盖端口占用后自动迁移、外部观测真实配置提交后 `SIGKILL`、两次冷启动和旧业务数据清理；sentinel 连接数为 0。
- CUA 使用独立 Bundle ID 和隔离 WebKit 检查首次页、无端口通用页、更新与关于分组、故障恢复、未知 Origin 恢复及菜单直达更新；实际观察 HTTP 403 后的任务标题、就地重试和检查结果反馈。
- 另有 19 个独立存储进程回归与 14 项发布配置检查通过；本机 Release 试用验证了原有面板数据迁移后的正常加载。
