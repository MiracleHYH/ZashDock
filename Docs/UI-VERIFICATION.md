# 原生 UI 实际验收记录

## 2026-11-05 原生交互调整与验收边界

本次根据 Apple 设计评审调整原生界面：移除通用设置中的端口输入、当前端口和选端口按钮，端口改为应用自动管理；配置恢复不再索取端口。面板更新入口打开更新页，检查和下载期间保留网页交互；进度与取消按任务集中显示，故障页突出与当前问题对应的首选操作。更新与关于继续明确区分 ZashDock 应用版本和 Zashboard 面板版本，关于页分组展示产品、项目和许可。帮助菜单提供“复制面板地址”用于远程 CORS 诊断。

本轮已通过 CUA 查看直接复用生产视图和命令的隔离评审 App（`build/design-review/`，独立 Bundle ID、临时路径及非持久 WebKit）：首次页保持下载按钮与导入图标；⌘, 打开设置，通用页仅显示窗口行为，没有端口输入或当前端口；更新页就近显示应用/面板版本，关于页展示图标、用途和分组链接。故障页实际只突出“重试打开面板”，其他恢复路径及技术详情折叠；点击重试成功打开虚构本地面板。未知数据位置恢复页没有端口输入和重置新数据入口。

实际从 View 菜单选择“检查 Zashboard 面板更新…”直接打开更新页。本次 GitHub 返回 HTTP 403 限流，弹窗使用“无法检查面板更新”标题，提供“重试检查”和“关闭”；关闭后更新页继续显示“检查未完成，请重试”。没有执行下载或安装。隔离 App 最后通过 ⌘Q 正常退出，未修改生产 Remote 或 WebKit 数据。

后台检查/准备安装时保留内容交互、取消状态及自动地址迁移由程序化回归覆盖；本轮没有以 CUA 实测真实下载期间的网页操作、深色/辅助功能外观或剪贴板地址。构建和回归证据见 [TESTING.md](TESTING.md)。下方 2026-10-23 的截图与操作记录保留历史意义。

## 工具环境说明

普通受限 Shell 执行 `open` 曾返回 LaunchServices `-10827 / kLSNoExecutableErr`。只读检查确认 Bundle 中的 `Contents/MacOS/ZashDock`、Debug dylib 和 `CFBundleExecutable` 实际存在且名称一致。随后仅针对同一条精确路径 `open` 命令使用工具沙箱外执行权限，命令成功，窗口正常恢复。未重置 LaunchServices、修改签名或更改系统设置。

因此本记录将该次 `-10827` 归为工具执行环境限制，不将其写为产品缺陷。后续关闭窗口／重开与完全退出／重开验证使用的是成功的系统 `open` 路径。

一次 CUA 重绑定曾返回 ScreenCaptureKit `-3811` 捕获错误；随后只读辅助功能状态正常，验收继续。`noWindowsAvailable`、`App quit` 和退出后 `procNotFound` 则与实际窗口或进程已关闭的观察一致，并通过应用清单交叉确认。
